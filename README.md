# Диагност ПК

Один файл, который запускается на клиентском компьютере и отвечает на вопрос,
который задают чаще всего: **«у меня выключается сам, почему?»**

Не список ошибок, а разбор: что произошло → почему → что проверять.

## Запуск

Двойной клик по `Диагност-ПК.cmd`. Скрипт сам запросит права администратора —
без них не читаются счётчики SMART дисков.

Или из консоли:

```powershell
powershell -ExecutionPolicy Bypass -File Diagnose-PC.ps1
powershell -ExecutionPolicy Bypass -File Diagnose-PC.ps1 -Days 60        # глубже копать
powershell -ExecutionPolicy Bypass -File Diagnose-PC.ps1 -NoHtml        # без HTML
powershell -ExecutionPolicy Bypass -File Diagnose-PC.ps1 -OutDir D:\Клиент\Иванов
```

Отчёты складываются в папку `Отчёт-ПК-<дата>` рядом со скриптом:

| Файл | Зачем |
|---|---|
| `Диагностика-отчёт.html` | Открыть в браузере, отдать клиенту или распечатать |
| `Диагностика-текст.txt` | Быстро глянуть, вставить в ответ |
| `Диагностика-данные.json` | Машинные данные для своей базы и сравнения машин |

## Почему журнал, а не «датчик температуры»

Система Windows не умеет говорить «почему выключилось». Она пишет факты, и
самые важные из них выглядят неприлично просто. Например:

**`BugcheckCode = 0` в событии Kernel-Power 41** — отключение было **без синего
экрана**. Значит питание пропало раньше, чем система успела что-то записать.
Это совсем другой диагноз, чем 41 с кодом `0x124`, и лечится совсем иначе.

Код читается из XML события, а не из текста сообщения: у 41 поле `Message`
пустое, наивный парсер его не видит вообще.

## Связь событий по времени — главное

Самая частая ошибка при разборе — **связать то, что не связано**. Поэтому
программа сравнивает время:

- ищет ошибки **до** отключения (диск, перегрев, WHEA, синий экран);
- `Ntfs 98` после сброса помечает как **следствие**, а не причину: Windows
  ставит проверку диска при следующей загрузке после жёсткого выключения;
- если перед отключением пусто — так и пишется, и делает вывод: журнал молчит,
  значит отключилось не ПО, а питание.

Пример из реального прогона (этот же компьютер):

```
09.10.2026 17:48  — событий-причин перед отключением нет  (после: Ntfs 98 ×2 — следствие)
24.09.2026 10:57  — событий-причин перед отключением нет  (после: Ntfs 98 ×2 — следствие)
```

Вывод: питание. И отдельно — 500+ ошибок накопителя, но они **вне** этих
отключений, то есть другой дефект. Программа их не смешивает.

## Что проверяется

| Блок | Что смотрит | Зачем |
|---|---|---|
| Питание и отключения | Kernel-Power 41/42, EventLog 6008, BSOD 1001, дампы, коды BSOD с расшифровкой | Отключилось ПО или пропало питание |
| Температуры | ACPI-датчики, `nvidia-smi`, троттлинг Kernel-Processor-Power 37 | Перегрев отключает систему сам |
| Ошибки железа | WHEA 17/18/19/20/47 | Процессор или память сообщили сами |
| Диски | `disk` 7/11/15/51/153, `storAHCI`/`stornvme` 129, SMART, `Ntfs` 98 | Диск теряет связь с системой |
| Память | Планки, XMP/EXPO (паспортная против рабочей), результаты теста Windows | Разогнанная память выключает ПК без ошибок |
| Устройства | `Win32_PnPEntity` с ошибками, драйвер-виновник из BSOD | Конфликты и сломанные драйверы |
| Прочее | Отключения во сне, ожидающие обновления, отложенная перезагрузка | Мелочи, но часто объясняют повторы |

## Чего программа не делает

Честно о границах — чтобы не тратить время клиента:

- **Не измеряет БП.** В Windows нельзя. Только по косвенному признаку: если
  перед отключением журнал пуст, а температуры в норме — причина в питании.
  Дальше БП проверяют тестером под нагрузкой.
- **Без прав администратора** не читаются детальные счётчики SMART
  (температура, износ, переназначенные сектора) и часть журналов. Отчёт прямо
  скажет, что запущен без прав.
- **Не лечит.** Ничего не чинит, не удаляет, не меняет настройки. Только
  читает и показывает. Любая правка — отдельным шагом и с согласия.
- **Не знает БП и материнскую плату по частям.** Видно модель платы и версию
  BIOS, но не то, какой именно блок питания стоит.
- **Температуры процессора часто недоступны** через WMI — это нормально для
  десктопов. Тогда программа пишет, что данных нет, и советует HWiNFO или
  LibreHardwareMonitor, а не выдумывает цифру.

## Грабли, на которые программа наступает специально

Их стоит знать, если будешь править скрипт:

- **ID события не уникален.** `37` и `55` есть и у перегрева процессора, и у
  службы времени. Фильтр только по ID принимает синхронизацию времени за
  перегрев. Везде фильтр по провайдеру.
- **`Get-WinEvent -MaxEvents` отдаёт новейшие N записей и молча теряет
  старые.** Общий дамп журнала System на этом компьютере прятал 4 из 5
  аварийных отключений. События собираются точечно, по провайдеру.
- **`H` — встроенный псевдоним `Get-History`.** Функция с таким именем
  не вызывается никогда: `H 'текст'` уходит в историю команд, и отчёт
  получается пустым. В скрипте помощник называется `Add-Html`.
- **`@($list[object])` в PowerShell 5.1 бросает «Argument types do not
  match».** Ошибка гасится глобальным `SilentlyContinue`, и строки просто
  теряются из отчёта. Отсюда массивы, а не `List[object]`.
- **Файл скрипта обязан быть в UTF-8 с BOM.** Без BOM Windows PowerShell 5.1
  читает его как ANSI, кириллица ломает парсер — и программа не запускается
  вообще. Правь скрипт через редактор, который сохраняет BOM.
- **`Ntfs 55` — это не ошибка диска**, а «восстановление громкости после
  перезагрузки». Ошибки накопителя живут у провайдера `disk`.

## Проверено на живом компьютере

Прогонялось на Windows 11 с реальной историей отключений: 5 × Kernel-Power 41
с `BugcheckCode = 0`, 5 × EventLog 6008, 125 × Ntfs 98, 500+ ошибок `disk` 51,
память 32 ГБ без разгона, NVIDIA GTX 1060.

Программа верно отделила отключения (питание) от ошибок накопителя (отдельный
дефект) и не выдумала связь между ними — хотя Ntfs 98 и по времени совпадал.

## Хочешь добавить проверку

Всё в одном файле, порядок такой:

1. Собрать данные — рядом с другими `$ev*` через `Get-Events`
2. Разобрать и оценить — `Add-Finding 'CRIT' 'Область' 'Заголовок' 'Что' 'Почему' 'Что делать'`
3. Связать с отключением — `Add-Chain 'Симптом' 'Улика' 'Причина' 'Что проверить' 1`

Цепочки сортируются по приоритету и идут первыми — это то, что мастер читает
в первую очередь.
